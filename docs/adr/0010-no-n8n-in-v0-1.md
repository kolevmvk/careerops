# ADR-0010: No n8n in v0.1

- **Status:** Accepted
- **Date:** 2026-09-15
- **References:** SPECIFICATION §0

## Context

v1.0 proposed n8n for ingestion, reminders and scheduled processing. For a single-user system this adds a service to host, secure and back up, and its flagship workflow (parse and match) is core domain logic.

## Decision

Use Postgres triggers, `pg_cron`, Supabase database webhooks and server routes. Revisit n8n only for integrations with no domain logic.

## Consequences

- Fewer moving parts; core logic stays tested in code.
- Notification integrations are written as code.
